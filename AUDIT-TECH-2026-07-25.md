## Находки

### T1 [CRITICAL] `func` — документированная фича, которой нет в рантайме

`func add(a,b){ return a + b }` компилируется без ошибок, лежит в
`CHEATSHEET.md:57` («function (sugar over call/return)») и в
`LANGUAGE.md:193-196`. Но лоуринг **не создаёт вызов**:

```
goto __fnskip1        // перепрыгнуть тело
label __fn_add        // ← тело функции
set __ret = a + b
return
return                // дубль: явный + авто-дописанный
label __fnskip1
set x = add(2,3)      // ← вызов остался ВЫРАЖЕНИЕМ
```

`add(2,3)` уходит в вычислитель выражений, а тот знает только 28
встроенных функций. Эмпирически, на живом отгружаемом evaluator'е:

```
2+3          => 5
add(2,3)     => THREW: unknown function add()
floor(7/2)   => 3
```

В C# (`LvnExpression.cs`) поддержки пользовательских функций тоже нет —
только те же 28 `case`'ов. По `CAPABILITIES.md` §4 ошибка в выражении
«деградирует мягко» → игрок получает **молчаливый 0**. Тело `__fn_add`
при этом мёртвый код, который никто не исполняет.

**Диагностическая ирония:** валидатор ЧЕСТНО предупреждал
(`__fn_add is never targeted`, `return but no call`) — предупреждения были
ПРАВДОЙ. Естественное прочтение («ложные срабатывания на лоуринге func»)
их и похоронило. Я сам сначала прочёл их именно так.

Почему это критично именно для нашей ставки: агент, читающий шпаргалку,
применит `func` естественно (я применил, без подсказки) и получит тихие
нули. Гейт при этом даёт 2 варнинга, которые агент починить не может →
он либо выпилит абстракцию, либо начнёт игнорировать варнинги. Оба
исхода ломают главный цикл «ИИ пишет → компилятор ловит».

Живой контент не задет: `func` не используется НИ в одном из 12
жанровых примеров, ни в `examples/`, ни в проде (Cold чист; `__fn_` есть
только в дев-скриптах `wardrobe-test`/`rpg-inv`). И не используется он
ровно потому, что CI-гейт требует 0 варнингов — фичу молча обходили.

**Развилка:** либо доделать (лоурить вызов в `call` + кадр аргументов,
либо научить вычислитель пользовательским функциям), либо убрать из
языка и документации. Половина хуже обоих вариантов.

### T2 [HIGH] Словарь op'ов имеет 4 реализации, закреплены тестом 2

| Реализация | Роль | Закреплена? |
|---|---|---|
| `lvn/validate.go` `KnownOps` | компилятор/валидатор | эталон |
| `lvn-lang/grammar.json` | IDE, VS Code, подсветка | ✅ `TestKnownOpsMatchGrammar` |
| C# `LvnPlayer`+`StagingOps`+`VnStage` | референсный плеер | ❌ ничем |
| `panel/public/play/core.js` | веб-плеер/playground | ❌ ничем (частичный by design) |

`LvnPlayer.cs:741` — `default:` на неизвестном op'е: «Unregistered unknown
ops keep flowing to the stage (which ignores them)». Молча. Принцип
репозитория «Unknown is an error, never a silent skip» держится только на
компиляторе; на рантайме он **не держится вообще**.

Живое доказательство — сегодняшний `wardrobe_show`: добавлен в
grammar.json и в KnownOps, а реализован в `NovelApp.cs` — то есть в
пакете **shell**. Потребитель одного `lvn-engine` (наш публичный UPM-путь
из README!) получает на этом op'е тихий no-op, и ни один тест не краснеет.

T1 — тот же класс дефекта, но на уровне компилятора: он эмитит лоуринг,
которого не реализует ни один рантайм.

**Что нужно:** conformance-корпус — набор `.lvn` + ожидаемые наблюдаемые
эффекты, который ОБЯЗАН проходить каждый рантайм (C#, JS, будущие). Плюс
дешёвый тест «каждый `KnownOps` имеет обработчик в C#». Это превращает
«4 реализации дрейфуют» в механически проверяемый инвариант.

### T3 [MEDIUM] `CAPABILITIES.md` противоречит сам себе

Файл заявлен как «verified against the sources» и по стратегии —
API-документ для ИИ-агента. Противоречия внутри одного файла:

- §6: `defanim`/`play` — «❌ no (planned)»; §8: «✅ `defanim`/`play` work».
- §8: «❌ **No player text input** in the script (there is no
  `prompt`/`input`)»; §1 при этом документирует рабочий op `input` с
  полями, и он реально исполняется (`case "input"` в LvnPlayer и в JS).

Для человека это шум. Для агента документация **и есть** API —
противоречие прямо порождает неверный код (агент либо не воспользуется
`input`, либо решит, что `defanim` недоступен, и наплодит обходов).
Отсюда: самосогласованность доков заслуживает CI-гейта, а не вычитки.

## Эксперимент: проверка центрального обещания

Обещание — «an LLM writes a complete game in one shot», гейт —
`convert && validate` до 0 варнингов. Проверил на себе честно: прочитал
только `CHEATSHEET.md` (119 строк), написал с одной попытки игру жанра,
которого нет в `howto/` — торговые переговоры караванщика: карты
(`put`/`get`/`keys`/`del`), `for` по ключам, `while`, `func`, таймерный
выбор, текстовый ввод, вложенные `if/else`, реактивный HUD, `save`,
`hint`, `fade`, `tint`, `audio`. 133 команды.

**Результат: скомпилировалась и заработала с первой попытки.** Все 3
варнинга — из `func` (T1), то есть из дефекта движка, а не моих ошибок.
Ни одной синтаксической ошибки, ни одного «а как тут» — шпаргалки
хватило.

Это сильный сигнал: язык действительно one-shot-friendly для LLM, и
ставка на «язык века ИИ» технически обоснована. Ровно поэтому T1 дорог —
он бьёт в единственное место, где цикл замыкается.

Артефакт: `caravan.lvns` в скратчпаде сессии.

## Оценка завершённости

По продуктам, а не одним числом — они очень разной готовности.

| Продукт | Готовность | Чем ограничен |
|---|---|---|
| Язык + `lvnconv` | **~90%** | T1; компакция `.lvns` отложена; O3/O16 из вчерашнего аудита |
| Unity-рантайм | **~85%** | контракт op'ов не закреплён (T2); UITK P2/P3 |
| Shell (новелла-апп) | **~80%** | живой APK против прода играет; шлифовка экранов |
| Importer (articy/ink) | **~80%** | связность ADPD-графа (Jump/пины) — последний тяжёлый кусок |
| Studio (IDE + админка) | **~75%** | эргономика по фидбеку партнёра: многословность `.lvns`, гардероб |
| Services (сервер) | **~70%** | потолок модели данных: JSON-файлы + глобальный мьютекс |
| Дистрибуция (playground/доки/MCP) | **~70% от сделанного, но ~20% от нужного** | тут работы меньше всего относительно стратегического веса |

**Как движок — ~85% до честной v1.0.** Как продуктовая линейка — ~45–50%:
инженерия сильно опережает адопшн.

Отдельно про потолок сервера: ноль баз данных, 3 внешние зависимости
(`rardecode`, `x/image`), атомарная запись файлов + глобальный write-mutex.
Для «движок, который любой поднимет за минуту» это **достоинство**, и его
надо защищать. Для запущенного тайтла с живым кошельком/лидербордами это
жёсткий потолок. Решение — не «переписать на постгрес», а сделать шов
хранилища явным ДО реального биллинга, чтобы замена была заменой
адаптера, а не сервера.

## Куда упор (по убыванию отдачи)

1. **Conformance-корпус op'ов** (T2). Дёшево, закрывает целый КЛАСС
   дефектов, к которому принадлежат и `wardrobe_show`, и `func`. Пока
   его нет, каждый новый op — это новый шанс тихого расхождения ×4.
2. **Развязать `func`** (T1) — доделать или убрать. И принять правило:
   *в документации не живёт ничего, что не покрыто гейтящимся примером.*
   12 жанровых примеров уже гейтятся в CI — расширить гейт так, чтобы
   каждая документированная конструкция встречалась хотя бы в одном.
   Это механически исключает фантомные фичи как класс.
3. **Гейт самосогласованности доков** (T3) — потому что при ставке
   «наведи агента на llms.txt» документация является API.
4. **Дальше — дистрибуция, а не фичи.** Движок опережает свою
   поверхность принятия. Словарь в 29 op'ов — это ДОСТОИНСТВО; каждый
   новый op умножается на проблему T2. Расти надо не вширь по фичам, а
   вглубь по надёжности и вширь по аудитории.
5. **Articy-импорт как корпоративный клин.** Двоичный `.adpd` не умеет
   больше никто. Это единственный путь забрать студию с готовым
   каталогом — сегодняшний реимпорт Cold как чистой функции пайплайна
   сделал этот клин предъявляемым.
