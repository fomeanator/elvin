# ТЗ на главного героя: лист поз

Первый и главный персонаж. Спрайтовой анимации НЕ делаем: движок переключает
статичные арты по команде из сценария, и на телефоне это выглядит как смена
кадра в комиксе. Поэтому нужны не фазы движения, а **состояния игры** — по одной
картинке на состояние.

Референс уже есть и утверждён: подросток в синей куртке не по размеру, поверх
рюкзак, тяжёлые ботинки, короткий меч. Все позы — тот же самый персонаж, та же
одежда, тот же меч.

---

## 1. Формат: ОДИН лист, строгая сетка

Генерируется **одна картинка** — лист из 15 клеток, который мы нарежем скриптом.
Поэтому требования к сетке жёстче, чем к рисунку: ошибка в приводке означает, что
персонаж будет прыгать по экрану при каждой смене позы, и переделывать придётся
весь лист.

| Параметр | Значение |
|---|---|
| Размер листа | **3500 × 4200 px**, ровно |
| Сетка | **5 столбцов × 3 строки**, клетка **700 × 1400 px** |
| Формат | **PNG, RGBA, фон полностью прозрачный** |
| Разделители | **НЕТ**: ни рамок, ни линий, ни номеров, ни подписей, ни фоновой шахматки |
| Отступы | **НЕТ**: клетки идут вплотную, первая начинается в пикселе (0,0) |

### Приводка внутри каждой клетки (самое важное)

Клетки нарезаются по координатам, поэтому персонаж должен стоять в каждой клетке
**на одном и том же месте относительно её границ**:

1. **Пол — низ клетки.** Расстояние от нижнего края клетки до самой низкой точки
   обуви — **от 2 до 10 px**. Не «примерно внизу», а именно у края. Ноль нельзя:
   пиксель, лежащий на самой границе, при нарезке достаётся СОСЕДНЕЙ клетке и
   появляется там полоской у верхнего края.
2. **Голова — одна высота.** Верх волос отстоит от верхнего края клетки на
   **90–180 px** во ВСЕХ клетках. Наклонился, замахнулся, согнулся — всё равно в
   эту полосу.
3. **Центр — центр клетки.** Середина корпуса (грудина) на горизонтальной
   середине клетки, допуск **±25 px**. Меч и руки могут уходить в стороны, корпус
   — нет.
4. **Ничего не выходит за клетку.** Клинок, плащ, брызги — целиком внутри своих
   700 × 1400. Что вылезло к соседу, то при нарезке обрежется и будет торчать в
   чужом кадре.
5. **Один и тот же человек, один масштаб.** Рост фигуры одинаков во всех клетках
   (±20 px). Та же куртка, тот же рюкзак, тот же меч, тот же свет.

### Чего на листе быть не должно

- Текста, цифр, названий поз, водяных знаков.
- Тени на землю (её рисует движок) и любых «подставок» под ногами.
- Обводки клеток и фоновых плашек: фон — только прозрачность.

## 2. Что в какой клетке

Порядок жёсткий: по нему будет резать скрипт. Считаем слева направо, сверху вниз.

### Строка 1 — разговор (одна и та же стойка, разные лица)

| № | Клетка | Файл после нарезки | Что на картинке |
|---|---|---|---|
| 1 | строка 1, столбец 1 | `pose_calm.png` | стоит прямо, меч опущен, лицо спокойное, смотрит в камеру |
| 2 | 1-2 | `pose_angry.png` | та же стойка, плечи вперёд, брови сведены |
| 3 | 1-3 | `pose_smile.png` | та же стойка, расслабленнее, усмехается |
| 4 | 1-4 | `pose_scared.png` | отшатнулся на полшага, глаза широко, меч вздёрнут |
| 5 | 1-5 | `pose_tired.png` | сутулится, меч висит, дышит тяжело |

Стойка в этих пяти клетках должна быть **максимально одинаковой** — меняется
только лицо и мелочи корпуса. Это самые частые кадры: почти вся игра — разговоры.

### Строка 2 — бой

| № | Клетка | Файл | Что на картинке |
|---|---|---|---|
| 6 | 2-1 | `pose_guard.png` | боевая стойка: ноги расставлены, меч перед собой |
| 7 | 2-2 | `pose_attack.png` | замах: меч над головой, корпус развёрнут |
| 8 | 2-3 | `pose_strike.png` | момент удара: меч прошёл по дуге, след клинка |
| 9 | 2-4 | `pose_hurt.png` | отброшен назад, рука прикрывает бок, лицо искажено |
| 10 | 2-5 | `pose_down.png` | на одном колене, опирается на меч |

### Строка 3 — магия и итоги

| № | Клетка | Файл | Что на картинке |
|---|---|---|---|
| 11 | 3-1 | `pose_cast.png` | свободная рука поднята, в ней светится кристалл |
| 12 | 3-2 | `pose_win.png` | выпрямился, меч поднят вверх |
| 13 | 3-3 | `pose_think.png` | рассматривает что-то в руке, голова наклонена |
| 14 | 3-4 | `pose_walk.png` | шаг вперёд, в движении, меч опущен |
| 15 | 3-5 | `pose_talk.png` | говорит: рука в жесте, рот приоткрыт, лицо живое |

Из твоего листа из восьми кадров сюда просятся: кадр 1 → `attack`, кадр 4 или 5 →
`strike`, кадр 7 → `guard`, кадр 8 → `calm`. Остальные — фазы одного движения, для
статики не нужны.

## 3. Как включается в игру


Одна запись в `manifest.json`, блок `sprites`:

```json
"ec_hero": {
  "name": "Герой",
  "color": "#8a9ab5",
  "layers": [
    { "url": "/content/sprites/ec_hero/pose_{pose}.png" }
  ],
  "defaults": { "pose": "calm" },
  "axes": {
    "pose": ["calm", "angry", "smile", "scared", "tired",
             "guard", "attack", "strike", "hurt", "down",
             "cast", "win", "think", "walk", "talk"]
  }
}
```

После этого в сценарии:

```
actor ec_hero left pose=calm
{имя}: Где я? И почему у меня в руке чужой меч?

actor ec_hero pose=attack
«Ты бьёшь первым.»
actor ec_hero pose=strike
boom
«Меч прошёл по костям, и они рассыпались.»

actor ec_hero pose=hurt
hurtfx
«Удар отбросил тебя к стене.»
```

Удобнее — сделать в `ec-mechanics.lvns` короткие имена, тогда сценарий читается
как раскадровка:

```
def hero actor ec_hero left
def hero_hit actor ec_hero left pose=strike
def hero_hurt actor ec_hero left pose=hurt
def hero_win actor ec_hero left pose=win
```

и в главе: `hero_hit` вместо длинной строки.

## 4. Второе оружие — без перерисовки тел

Когда мечей станет больше одного, тела заново рисовать не придётся. В пути слоя
можно подставлять **сразу две оси**, и движок соберёт нужную комбинацию:

```json
"layers": [
  { "url": "/content/sprites/ec_hero/body_{pose}.png" },
  { "url": "/content/sprites/ec_hero/wpn_{weapon}_{pose}.png" }
],
"axes": {
  "pose":   ["calm", "attack", "strike", "..."],
  "weapon": ["sword", "axe", "staff", "none"]
}
```

Тогда для нового оружия нужны только маленькие картинки самого оружия по числу
поз, где оно видно, — а не тринадцать новых полноростовых рендеров. Тела при
этом рисуются **с пустой кистью** (кулак сжат так, будто держит рукоять), и
оружие ложится сверху отдельным слоем.

Два ограничения, которые надо знать заранее:

- слой нельзя повернуть — под каждый хват нужна своя картинка оружия, поэтому
  файл и называется `wpn_{weapon}_{pose}.png`, а не просто `wpn_{weapon}.png`;
- отсутствующий файл слоя просто не рисуется, ошибки не будет. Это удобно:
  можно завести ось `weapon` заранее и добавлять оружие по одному, ничего не
  ломая.

**Если решишь идти этим путём сразу** — скажи, и в разделе 2 меч будет заменён на
пустую кисть, плюс отдельный маленький лист на меч (13 картинок оружия вместо
одной впечатанной). Для одного меча это лишняя работа, для трёх — уже выгодно.

## 5. Гардероб: оружие как выбор игрока

В движке есть система гардероба — она умеет показать игроку набор вариантов по
оси, запомнить выбор между сессиями и записать его в переменную истории. Оружие
ложится в неё естественно: ось `weapon` объявляется слотом гардероба, и тогда
игрок сам выбирает, чем идти, а сценарий узнаёт об этом из переменной и меняет
`мощь` в боевой формуле.

Это следующий шаг после того, как появится второе оружие: пока оружие одно,
выбирать не из чего.

## 6. Нарезка и проверка приводки

Лист нарезается скриптом, который заодно ИЗМЕРЯЕТ приводку — глазами такое не
проверяют:

```sh
python3 tools/cut-sheet.py путь-к-листу.png server/content/sprites/ec_hero
```

Скрипт режет 5×3, раскладывает по именам из раздела 2 и печатает по каждой позе:
где подошвы, где верх головы, где центр корпуса, — и отмечает выход за допуски
(пол 2–10 px от низа, голова 90–180 px от верха, центр ±25 px). Если приводка
поехала, видно сразу и понятно, какую клетку перерисовывать: переделывать надо
одну клетку, а не весь лист.

Дальше — проверка глазами на то, что скрипт не умеет: один ли это человек, та же
ли куртка, тот же ли меч, нет ли текста.
4. Ни на одной картинке нет текста.
