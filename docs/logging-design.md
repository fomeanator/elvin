# Логирование: картина целиком и чек-лист

Цель Ильи (15.09.2026): **лучшая система логирования — дешёвая, быстрая,
полноинформационная**. Вопросы, на которые она обязана отвечать: чем
пользуются, куда жмут и сколько раз, сколько времени проводят на каждом
экране, докуда дочитывают главу построчно («0-ю строку увидели 100, дальше
кликнули 97…»), где именно проблема; плюс сбои и тормоза. Илья: «по идее это
грамотным логом делается» — не событие на каждое движение, а правильно
устроенный поток. Задачи трекера — TR-86 (логи), TR-126 (использование).

## Картина

**Три потока, у каждого своя цена.**

1. **Чёрный ящик на устройстве** — всё, включая Trace, кольцом по дням с
   потолком; на сервер не едет, пока не попросили. Полнота без цены.
2. **Счётчики** — использование (`ui_use`: тапы по элементам и секунды по
   экранам, одно событие в минуту), окна кадров (`[lvn-perf] W`, раз в 10 с).
   Дёшево, потому что минута — одна строка в несколько сотен байт, а не
   тысяча событий.
3. **События смысла** — старт/конец/уход из главы с индексом строки, метки,
   развилки, деньги, сбои. Редкие и точные; из них считаются воронки.

**Коды вместо текста.** Всё, что едет часто, — короткими ключами по
словарю (docs/client-logs.md), без «na», без повторов run/build в каждой
строке; текст — только там, где его читает человек и он редкий (ошибка,
исключение). Экран и элемент называются своими именами из дерева
интерфейса, а не описанием.

**Из счётчиков и событий — ответы, а не сырьё.** Сервер сворачивает дни
(rollup), панель показывает: «Использование» (экраны по времени, во что
жмут), «Внутри главы» по меткам и по строкам (дошло / от входа / потеряно —
где обрыв), «Обрывы» с восстановленным кадром, «Здоровье», «Деньги».

**Быстро.** На тап — инкремент в словаре по имени, найденному по цепочке
родителей; на кадр — ничего сверх счётчика; строка складывается раз в
минуту. Ни строк, ни JSON в горячем пути.

## Чек-лист

- [x] Экономия замеров: коды, пол 50 мс, без стеков у info (cc7e9a5e, TR-86).
- [x] `LvnUsage`: тапы по элементам и секунды по экранам, одно событие в минуту и при уходе в фон (TR-126).
- [x] Свёртка `usage` на сервере, отчёт `/v1/analytics/usage`, панель «Использование».
- [x] Цепочка «нажал → сделал» (Илья 16.09): устройство помнит последний тап полминуты, первое значимое действие после него (событие аналитики или переход на экран) считается паре «элемент>исход»; в отчёте доля от тапов по элементу = конверсия нажатия.
- [x] Воронка по строкам: `/v1/analytics/slides?by=line`, панель «По меткам / По строкам».
- [x] Чёрный ящик на устройстве: `LvnBlackBox` — все строки с Trace в файлы по дням, потолок 30 МБ, кольцо 200 строк в памяти (TR-86, этап 1).
- [x] Отклонения с хвостом: исключение, ошибка, кадр > 500 мс, старт > 8 с, обрыв прошлого запуска (метка сессии). Шторм закачек и зависшая сеть — пока только строками без хвоста.
- [x] Подробный лог по указанию сервера: ответ `/v1/log/client` несёт `log.until`, устройство шлёт Trace до срока; пульт — `PUT /v1/admin/log-level {device, hours}`, панель «Здоровье → Подробный лог с устройства».
- [x] Запрос куска кольца задним числом: `PUT /v1/admin/log-fetch {device, from, to}` → устройство высылает строки периода уровнем `ring` с исходным временем и подтверждает (этап 2).
- [x] «Что прислал»: `/v1/admin/client-logs/sessions` (сессии дня: строки по уровням, отклонения, fps, худший кадр, окна с рывками), хвост дня с фильтрами по сессии/уровню/тегу; раздел панели «Логи» с пультом (этап 3).
- [x] Воронка по шагам по игрокам (`/v1/analytics/sequence?steps=`): шаги «событие:условия», особые `progress:chapter=X,at>=N` и `screen=X`; у каждого обрыва — куда ушли вместо следующего шага (Илья 16.09: «только точки знать не поможет»).
- [x] Пути с экрана (`/v1/analytics/paths?screen=`): доля игроков экрана по нажатым элементам и куда попали — «какой процент на магазин кликает в меню».
- [x] Путь игрока (`/v1/analytics/player?user=`): лента событий одного игрока по времени.
- [x] Время на строке (Илья 16.09 «делай»): устройство копит секунды по индексу команды, пока стоит на строке (свёрнутое и паузы дольше 5 минут не считаются), список `dwell` уезжает с chapter_finish/chapter_abandon; свёртка главы `dw/dn`, в «По строкам» колонка «на строке» (среднее по сессиям, ≥ 60 с подсвечено).
- [x] Склейка логов (Илья 16.09: «инкременторы, сжатый архив, только важное, серую массу вырезают»): сырой дневник живёт двое суток, потом день склеивается — сводка `<день>.summary.json` (строки по уровням и тегам, самые частые шаблоны, сессии с fps и отклонениями) и архив важного `<день>.keep.jsonl.gz` (ошибки, исключения, предупреждения, отклонения с хвостом, заголовки устройств, ring, trace); окна и кадры замеров и прочие info вырезаются; архив живёт 60 суток; хвост дня и сессии читаются из архива как из сырья.
- [ ] ИИ-склейка поверх сводок: «что случилось за день» словами по отклонениям и шаблонам (после того, как накопятся сводки).
- [ ] Словарь экранов и элементов для панели: человеческие имена вместо `GachaScreen` / `gacha-spin`.

## Как проверить

1. Поиграть минуту-две: главная, гардероб, крутки, глава. В панели
   «Аналитика → Использование» — экраны с временем и тапами.
2. «Аналитика → Обрывы → глава → Внутри главы → По строкам»: каждая реплика
   с числом дошедших и потерями между соседними.
3. `/v1/admin/client-logs`: строки `[lvn-perf] S`/`W` короткие, у info нет
   `stack`.
