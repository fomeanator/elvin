# Логирование: картина целиком и чек-лист

Цель Ильи (15.09.2026): **лучшая система логирования — дешёвая, быстрая,
полноинформационная**. Вопросы, на которые она обязана отвечать: чем
пользуются, куда жмут и сколько раз, сколько времени проводят на каждом
экране, докуда дочитывают главу построчно («0-ю строку увидели 100, дальше
кликнули 97…»), где именно проблема; плюс сбои и тормоза. Илья: «по идее это
грамотным логом делается» — не событие на каждое движение, а правильно
устроенный поток. Задачи трекера — TR-86 (логи), TR-126 (использование).

## Картина

**Три потока, у каждого своя цена.**

1. **Чёрный ящик на устройстве** — всё, включая Trace, кольцом по дням с
   потолком; на сервер не едет, пока не попросили. Полнота без цены.
2. **Счётчики** — использование (`ui_use`: тапы по элементам и секунды по
   экранам, одно событие в минуту), окна кадров (`[lvn-perf] W`, раз в 10 с).
   Дёшево, потому что минута — одна строка в несколько сотен байт, а не
   тысяча событий.
3. **События смысла** — старт/конец/уход из главы с индексом строки, метки,
   развилки, деньги, сбои. Редкие и точные; из них считаются воронки.

**Коды вместо текста.** Всё, что едет часто, — короткими ключами по
словарю (docs/client-logs.md), без «na», без повторов run/build в каждой
строке; текст — только там, где его читает человек и он редкий (ошибка,
исключение). Экран и элемент называются своими именами из дерева
интерфейса, а не описанием.

**Из счётчиков и событий — ответы, а не сырьё.** Сервер сворачивает дни
(rollup), панель показывает: «Использование» (экраны по времени, во что
жмут), «Внутри главы» по меткам и по строкам (дошло / от входа / потеряно —
где обрыв), «Обрывы» с восстановленным кадром, «Здоровье», «Деньги».

**Быстро.** На тап — инкремент в словаре по имени, найденному по цепочке
родителей; на кадр — ничего сверх счётчика; строка складывается раз в
минуту. Ни строк, ни JSON в горячем пути.

## Чек-лист

- [x] Экономия замеров: коды, пол 50 мс, без стеков у info (cc7e9a5e, TR-86).
- [x] `LvnUsage`: тапы по элементам и секунды по экранам, одно событие в минуту и при уходе в фон (TR-126).
- [x] Свёртка `usage` на сервере, отчёт `/v1/analytics/usage`, панель «Использование».
- [x] Воронка по строкам: `/v1/analytics/slides?by=line`, панель «По меткам / По строкам».
- [ ] Чёрный ящик на устройстве: кольцо с Trace, файлы по дням, потолок 30 МБ (TR-86, этап 1).
- [ ] Отклонения с хвостом Trace: исключение, кадр > 500 мс, старт > 8 с, шторм закачек, зависшая сеть, падение при прошлом запуске.
- [ ] Подробный лог по указанию с сервера (ответ `/v1/content/version`), срок сутки; запрос куска кольца задним числом (этап 2).
- [ ] Кнопки в панели у игрока: «Подробный лог на сутки», «Запросить период», «Что прислал» (этап 3).
- [ ] Словарь экранов и элементов для панели: человеческие имена вместо `GachaScreen` / `gacha-spin`.

## Как проверить

1. Поиграть минуту-две: главная, гардероб, крутки, глава. В панели
   «Аналитика → Использование» — экраны с временем и тапами.
2. «Аналитика → Обрывы → глава → Внутри главы → По строкам»: каждая реплика
   с числом дошедших и потерями между соседними.
3. `/v1/admin/client-logs`: строки `[lvn-perf] S`/`W` короткие, у info нет
   `stack`.
