# Свой террейн: исследование

Задача, поставленная так: земля должна нести рельеф, предметы обязаны сами
садиться на него, игрок — подниматься на пригорок, а не проходить сквозь. При
этом «сверхоптимизированный, но не уступающий обычным».

Документ разбирает, что для этого нужно, что уже сделано и чем наш подход
отличается от того, что даёт Unity Terrain.

---

## 1. Почему не Unity Terrain

Причина не в качестве — он хорош. Причина в том, что он **не переносится по
сети** и **не описывается текстом**, а на этом стоит весь движок.

| | Unity Terrain | Наш |
|---|---|---|
| Как задаётся | картой высот, нарисованной кистью | числами в строке скрипта |
| Как хранится | бинарный `TerrainData` в проекте | нигде: считается на месте |
| Как доставляется | только сборкой приложения | приезжает вместе со скриптом |
| Кто автор | человек с мышью | человек ИЛИ нейросеть |
| Вес | мегабайты на карту высот | сорок символов |

Ключевое — последнее. Автор пишет:

```
o3d id=земля shape=ground size="120,1,120" hills=1.6 hill_size=26 detail=0.45 seed=4
```

и получает рельеф. Нейросеть, которая пишет сцену текстом, картой высот
пользоваться не может — а числами может. Ради этого стоит отказаться от
редактора кистью.

Второе: террейн Unity тянет в сборку свой модуль и не умеет жить в бандле,
который мы стримим. Место, приехавшее по сети, обязано быть обычной геометрией.

---

## 2. Что уже работает

**Рельеф из формулы.** `Lvn3DTerrain` строит сетку и поднимает её тремя
октавами шума. Плотность — примерно клетка на полтора метра, потолок 240 клеток
на сторону.

**Высота в любой точке — аналитически.** Та же формула, по которой построен
меш, отвечает на вопрос «какая здесь высота» за несколько умножений. Это
основа всего остального: не нужны ни коллайдеры, ни лучи, ни физика.

**Предметы садятся сами.** `ground=1` ставит тело на землю; посев (`count=`)
сажает каждую копию отдельно. Автор не считает высоты — он их вообще не пишет.

**Ходьба по рельефу.** Камера держит запомненную высоту глаз над землёй и
следует за холмами. Высота глаз берётся в момент включения ходьбы: автор уже
поставил камеру, и подменять его число своим неправильно. Переход сглажен —
на ступеньке высота меняется скачком, и мгновенный подъём читается рывком.

---

## 3. Чего не хватает и что с этим делать

### 3.1. Рельеф под чужой геометрией

Аналитическая высота знает только про НАШУ землю. Если место приехало
бандлом — замок, склеп, мостовая, — высота там берётся перебором вершин
ближайшего меша: `O(n)` на каждый запрос. Для сорока надгробий это терпимо,
для тысячи травинок уже нет.

**Что делать.** Сетка ускорения: разбить вершины пола на клетки по два метра и
искать только в своей клетке и соседних. Построение — один раз при постановке
набора, запрос — константа. Это тридцать строк и снимает ограничение
полностью.

### 3.2. Уклон

Сейчас предмет ставится на высоту, но **не поворачивается по склону**: столб
на косогоре стоит отвесно, будто вкопан по уровню. Нормаль рельефа считается
из той же формулы двумя дополнительными выборками.

Нужно поле языка — не всё должно кланяться склону: дерево растёт вертикально,
а вот камень и упавшая плита ложатся по земле.

```
o3d id=плита model=... ground=1 slope=1     // лечь по склону
o3d id=дерево model=... ground=1            // остаться вертикальным
```

### 3.3. Слои поверхности

У Unity Terrain текстура смешивается из слоёв по карте. У нас земля одна на всю
площадь — тропа, трава и камень не различаются.

**Дешёвый способ**, не требующий карт: смешивать ПО САМОМУ РЕЛЬЕФУ.

- крутой уклон → камень (на склоне не держится почва);
- низина → грязь и мох (туда стекает вода);
- ровное и высокое → трава.

Это три выборки текстур и два смешивания в трипланаре, зато рельеф сразу
начинает читаться как местность, а не как холмистый ковёр. И — важно — автору
не нужно ничего рисовать: правило выводится из уже заданных чисел.

### 3.4. Уровни детализации

Сейчас вся земля — один меш постоянной плотности. На ста метрах при клетке
полтора метра это четыре тысячи клеток, то есть двадцать пять тысяч вершин, и
половина из них уходит на дальний план, где холм занимает три пикселя.

**Что делать.** Чанки по 32 × 32 метра, у каждого своя плотность по расстоянию
до камеры: ближние подробно, дальние вчетверо реже. Сшивать края чанков разной
плотности нужно аккуратно — иначе на стыке появляется щель; классическое
решение — «юбка» по краю чанка, полоска вниз, закрывающая шов.

Пока сцены новеллы небольшие (шестьдесят-сто метров), это не горит.

### 3.5. Коллизии для построек

Рельеф — не единственное, обо что игрок должен спотыкаться. В замке нужны
стены, перекрытия и лестницы, а формулы для них нет: это чужая геометрия.

**Что делать.** Автоколлизии: при постановке набора навесить меш-коллайдеры на
несущую геометрию (не на подсвечники), а ходьбу перевести на два луча — вниз и
вперёд. Тогда второй этаж работает сам собой: под ногами перекрытие — стоим на
перекрытии.

Оговорки, которые уже известны: стриппинг вырезает коллайдеры из сборки, если
на них нет явной ссылки (`class ID 64`), и построение меш-коллайдера на большой
модели занимает заметное время — вешать надо на загрузке, а не на первом шаге.

---

## 4. Что значит «не уступать обычным»

По пунктам, чем Unity Terrain реально силён и чем мы отвечаем:

| Возможность | Unity Terrain | Наш ответ |
|---|---|---|
| Карта высот кистью | да | числами; кисти не будет намеренно |
| Уровни детализации | да | чанки (3.4), пока не нужны |
| Слои текстур | по карте | по уклону и высоте (3.3) |
| Трава и деревья | свои системы | посев `o3d count=`, уже есть |
| Коллизия рельефа | коллайдер | формула, дешевле (есть) |
| Коллизия построек | — | автоколлизии (3.5) |
| Дырки, пещеры | да | нет и не планируется |
| Запекание освещения | да | наш свет считается в кадре |

Единственное, чего у нас не будет принципиально, — рисование рельефа рукой.
Всё остальное либо есть, либо сводится к понятной работе.

---

## 5. Порядок работ

1. **Сетка ускорения для чужого пола** (3.1) — снимает ограничение на число
   предметов, тридцать строк.
2. **Уклон** (3.2) — предметы перестают торчать из склона колом.
3. **Слои по уклону и высоте** (3.3) — самый заметный шаг для картинки.
4. **Автоколлизии построек** (3.5) — открывает замки и вторые этажи.
5. **Чанки и уровни детализации** (3.4) — когда сцены вырастут.

Первые три касаются только земли и не требуют физики вовсе. Четвёртый —
единственное место, где придётся впустить в движок геометрические запросы, и
это осознанная плата за возможность ходить внутри построек.
