# `ui` — интерфейс на языке

Цель: **на `.lvns` собирается любое дерево UI Toolkit**. Не набор готовых
виджетов, а тот же конструктор, которым написаны хаб и магазин, — только из
сценария.

## Зачем это вообще

Сейчас игровой интерфейс рисуется спрайтами сцены: `obj id=btn x=0.13 y=57%
width=0.092`. Голые числа, каждое подобрано вручную. Отсюда всё:

- элементы не знают друг о друге и налезают;
- сдвинешь одно — пересчитывай соседей;
- полоса здоровья в дуэли — **17 веток литеральных ширин**;
- поменяешь опорное разрешение — рассыпается всё разом (проверено 17.08).

Оболочка тем временем уже рисует флексом с темой, иконками и пружинами. `ui`
не строит раскладку заново — он **даёт языку доступ к той, что работает**.

## Форма

```
ui бой {
  panel at=bottom h=19% pad=2% bg=panel {
    row gap=3% {
      column grow=1 {
        text «{враг_имя}» size=13 color=warn
        bar value="{враг_хп / враг_хп_макс}" h=2.5% color=warn
      }
      column grow=1 {
        text «ТЫ» size=13 color=accent
        bar value="{дуэль_хп / дуэль_хп_макс}" h=2.5% color=accent
      }
    }
    row gap=2% justify=center pad_y=1% {
      button id=b_hit  «УДАР»  on_click=дп_удар
      button id=b_blk  «БЛОК»  on_click=дп_блок
    }
  }
}
```

`ui <имя> { … }` объявляет дерево. Повторное объявление с тем же именем
**заменяет** его целиком — это и есть обновление экрана.

```
ui бой hide      // спрятать, не разрушая
ui бой show
ui бой drop      // убрать совсем
```

## Элементы

| Элемент | Что это |
|---|---|
| `panel` | контейнер; всё остальное лежит внутри |
| `row` / `column` | контейнер с направлением (то же, что `panel dir=row`) |
| `text` | подпись; содержимое в «…», в нём работают `{выражения}` |
| `bar` | полоса заполнения: `value=` от 0 до 1 |
| `icon` | векторная иконка движка: `icon name=energy` |
| `image` | картинка по адресу: `image url=…` |
| `button` | нажимаемый; `on_click=<метка>` |
| `space` | пустое место; обычно с `grow=1` — распорка |
| `scroll` | прокручиваемый контейнер |

## Раскладка

Один в один флекс UI Toolkit — не свой диалект.

| Поле | Значения |
|---|---|
| `dir` | `row` \| `column` (у `panel`; по умолчанию `column`) |
| `gap` | зазор между детьми |
| `pad`, `pad_x`, `pad_y` | внутренние отступы |
| `justify` | `start` \| `center` \| `end` \| `between` \| `around` — вдоль направления |
| `align` | `start` \| `center` \| `end` \| `stretch` — поперёк |
| `grow`, `shrink`, `basis` | как делится свободное место |
| `w`, `h` | `40%`, `120` (единицы панели), `auto` |
| `at` | `top` \| `bottom` \| `left` \| `right` \| `center` \| `fill` — абсолютная привязка к родителю |
| `z` | порядок наложения |

**Единицы.** Проценты — от родителя. Голое число — единицы панели
(1080×1920). Это тот же контракт, что у остального языка; менять его нельзя,
см. `LvnPanel`.

## Вид

| Поле | Значения |
|---|---|
| `bg` | `#rrggbb`, `#rrggbbaa` или имя токена темы |
| `color` | цвет текста/полосы/иконки |
| `radius` | скругление |
| `edge` | толщина светящейся кромки темы (`0` — нет) |
| `opacity` | 0…1 |
| `size` | кегль текста |
| `weight` | `bold` |

**Токены темы** вместо литералов: `bg=surface`, `color=accent`, `bg=panel`.
Тогда смена `ui.browse.theme` перекрашивает и игровой интерфейс — а иначе он
останется единственным местом, живущим своей палитрой.

## Привязка к переменным

Любое поле, где есть `{…}`, **пересчитывается само**, когда переменная
меняется. Это и убивает 17 веток литеральных ширин:

```
bar value="{дуэль_хп / дуэль_хп_макс}"
text «Сердец {дуэль_хп} из {дуэль_хп_макс}»
```

Никакого «перерисуй» звать не надо: `set хп = хп - 1` меняет полосу.

## События

`on_click=<метка>` — прыжок по нажатию, как у `obj`. Нажатие само даёт отклик
(сквош и пружина), потому что это те же элементы, что в оболочке.

## Чего в v1 НЕТ

Честно, чтобы не искали:

- нет своих шейдеров и произвольной отрисовки — только дерево элементов;
- нет перетаскивания;
- нет ввода текста внутри `ui` (для него есть оп `input`);
- нет трёхмерного: `ui` живёт над сценой, а не в ней.

## Границы и риск

Раскладка — единственное место, где рантаймы (C#, JS-плеер, Canvas)
гарантированно разойдутся. Поэтому:

- каждый случай ложится в `conformance/cases` с первого дня;
- поля названы как в UI Toolkit, чтобы «правильное поведение» не приходилось
  придумывать — оно уже определено;
- JS-плеер поддерживает подмножество и **честно об этом сообщает**, а не
  рисует молча иначе.
