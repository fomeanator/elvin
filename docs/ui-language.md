# `ui` — интерфейс на языке

Цель: **на `.lvns` собирается любое дерево UI Toolkit**. Не набор готовых
виджетов, а тот же конструктор, которым написаны хаб и магазин, — только из
сценария.

## Зачем это вообще

Сейчас игровой интерфейс рисуется спрайтами сцены: `obj id=btn x=0.13 y=57%
width=0.092`. Голые числа, каждое подобрано вручную. Отсюда всё:

- элементы не знают друг о друге и налезают;
- сдвинешь одно — пересчитывай соседей;
- полоса здоровья в дуэли — **17 веток литеральных ширин**;
- поменяешь опорное разрешение — рассыпается всё разом (проверено 17.08).

Оболочка тем временем уже рисует флексом с темой, иконками и пружинами. `ui`
не строит раскладку заново — он **даёт языку доступ к той, что работает**.

## Форма

```
ui бой {
  panel at=bottom h=19% pad=2% bg=panel {
    row gap=3% {
      column grow=1 {
        text «{враг_имя}» size=13 color=warn
        bar value="{враг_хп / враг_хп_макс}" h=2.5% color=warn
      }
      column grow=1 {
        text «ТЫ» size=13 color=accent
        bar value="{дуэль_хп / дуэль_хп_макс}" h=2.5% color=accent
      }
    }
    row gap=2% justify=center pad_y=1% {
      button id=b_hit  «УДАР»  on_click=дп_удар
      button id=b_blk  «БЛОК»  on_click=дп_блок
    }
  }
}
```

`ui <имя> { … }` объявляет дерево. Повторное объявление с тем же именем
**заменяет** его целиком — это и есть обновление экрана.

```
ui бой hide      // спрятать, не разрушая
ui бой show
ui бой drop      // убрать совсем
```

### Стадия игры

```
ui бой  when=idle      // спрятать, пока идёт реплика или показан выбор
ui намёк when=say      // наоборот: виден ТОЛЬКО пока читают реплику
ui меню when=always    // по умолчанию
```

Без этого автор прятал дерево руками (`ui бой hide`) в каждой ветке — и одну
неизбежно забывал, отчего интерфейс оставался поверх разговора.

«Идёт реплика» — это **ожидание касания**, а не видимость окна: окно остаётся
на экране и после того, как игра ушла дальше, и по нему стадию определять
нельзя (проверено живьём — HUD пропадал навсегда).

Нижний этаж вдобавок **поджимается на высоту окна реплики**, поэтому
`at=bottom` означает «над диалогом», а не «под ним». Раньше отступ подбирали
руками, и он разъезжался на первом же длинном имени.

### Два этажа

```
ui бой  layer=hud             // по умолчанию: ПОД окном реплики
ui меню layer=over block=1    // поверх всего, тап мимо кнопок гаснет здесь
```

Один этаж не годится, и это выяснилось на первой же живой проверке: ряд
кнопок боевого интерфейса закрыл собой текст реплики. Игровой интерфейс
обязан уходить под окно диалога, а полноэкранное меню — лежать над ним, и то
и другое встречается в одной главе.

`block=1` — про касания, а не про порядок. Слой по умолчанию прозрачен для
тапа мимо кнопок: история продолжается, как продолжалась. Меню — наоборот:
тап по пустому месту меню не должен листать историю за его спиной.

## Элементы

| Элемент | Что это |
|---|---|
| `panel` | контейнер; всё остальное лежит внутри |
| `row` / `column` | контейнер с направлением (то же, что `panel dir=row`) |
| `text` | подпись; содержимое в «…», в нём работают `{выражения}` |
| `bar` | полоса заполнения: `value=` от 0 до 1 |
| `icon` | векторная иконка движка: `icon name=energy` |
| `image` | картинка по адресу: `image url=…` |
| `button` | нажимаемый; `on_click=<метка>` |
| `space` | пустое место; обычно с `grow=1` — распорка |
| `scroll` | прокручиваемый контейнер |

## Раскладка

Один в один флекс UI Toolkit — не свой диалект.

| Поле | Значения |
|---|---|
| `dir` | `row` \| `column` (у `panel`; по умолчанию `column`) |
| `gap` | зазор между детьми |
| `pad`, `pad_x`, `pad_y` | внутренние отступы |
| `justify` | `start` \| `center` \| `end` \| `between` \| `around` — вдоль направления |
| `align` | `start` \| `center` \| `end` \| `stretch` — поперёк |
| `grow`, `shrink`, `basis` | как делится свободное место |
| `w`, `h` | `40%`, `120` (единицы панели), `auto` |
| `at` | `top` \| `bottom` \| `left` \| `right` \| `center` \| `fill` — абсолютная привязка к родителю |
| `z` | порядок наложения |

**Единицы.** Проценты — от родителя. Голое число — единицы панели
(1080×1920). Это тот же контракт, что у остального языка; менять его нельзя,
см. `LvnPanel`.

## Вид

| Поле | Значения |
|---|---|
| `bg` | `#rrggbb`, `#rrggbbaa` или имя токена темы |
| `color` | цвет текста/полосы/иконки |
| `radius` | скругление |
| `edge` | толщина светящейся кромки темы (`0` — нет) |
| `opacity` | 0…1 |
| `size` | кегль текста |
| `weight` | `bold` |

### Шкала вместо чисел

Кегль — ступенью, а не числом:

| `size=` | что это |
|---|---|
| `xs` | подписи под элементом, сноски |
| `sm` | подсказки, единицы измерения |
| `base` | основной текст (по умолчанию у `text` и `button`) |
| `lg` | подзаголовок, крупная цифра |
| `xl` | заголовок экрана |
| `display` | витринный заголовок |

Отступы (`pad`, `pad_x`, `pad_y`, `gap`) целыми числами `1`…`6` берутся из той
же шкалы темы: `gap=3` — это ступень, а не «три пикселя». Проценты и пиксели
по-прежнему работают.

Зачем: «на глаз» даёт 14, 15 и 18 в соседних местах, и взгляд цепляется за
разнобой. Одинаковые вещи на разных экранах обязаны быть одного размера.

**Токены темы** вместо литералов: `bg=surface`, `color=accent`, `bg=panel`.
Тогда смена `ui.browse.theme` перекрашивает и игровой интерфейс — а иначе он
останется единственным местом, живущим своей палитрой.

## Привязка к переменным

Любое поле, где есть `{…}`, **пересчитывается само**, когда переменная
меняется. Это и убивает 17 веток литеральных ширин:

```
bar value="{дуэль_хп / дуэль_хп_макс}"
text «Сердец {дуэль_хп} из {дуэль_хп_макс}»
```

Никакого «перерисуй» звать не надо: `set хп = хп - 1` меняет полосу.

Живыми могут быть: `text`, `value`, `bg`, `color`, `hide`, `opacity`, `w`, `h`.
Отдельно стоит `hide` — узел исчезает и появляется без пересборки дерева:

```
button «ЗЕЛЬЕ 10» on_click=зелье hide="{золото < 10}"
```

Сверка идёт каждые 60 мс, и до стиля доходят только изменившиеся значения.

## События

`on_click=<метка>` — прыжок по нажатию, как у `obj`. Нажатие даёт отклик:
сквош с пружиной, подсветка под пальцем и **просадка на толщину кнопки** —
у кнопки есть тёмная нижняя грань, и под пальцем она садится на неё. Грань, а
не тень: теней в UI Toolkit нет вовсе, зато толщина читается даже лучше — палец
видит, что вдавил предмет, а не что мигнул цвет.

Прыжка одного мало, и это тоже нашлось живьём: игрок может стоять в `wait`,
ждать касания или показывать выбор, и запись новой позиции без пробуждения
оставляет его стоять — экран отвечает один раз, а дальше замирает. Нажатие
делает ровно то же, что клик по объекту сцены: прыжок, отмена ожидания, снятие
выбора, шаг вперёд.

Отсюда же берётся **экран без окна диалога**: дерево паркуется на длинном
`wait ms=`, а кнопка выигрывает гонку с таймером.

## Чего в v1 НЕТ

Честно, чтобы не искали:

- нет своих шейдеров и произвольной отрисовки — только дерево элементов;
- нет перетаскивания;
- нет ввода текста внутри `ui` (для него есть оп `input`);
- нет трёхмерного: `ui` живёт над сценой, а не в ней.

## Границы и риск

Раскладка — единственное место, где рантаймы (C#, JS-плеер, Canvas)
гарантированно разойдутся. Поэтому:

- каждый случай ложится в `conformance/cases` с первого дня;
- поля названы как в UI Toolkit, чтобы «правильное поведение» не приходилось
  придумывать — оно уже определено;
- JS-плеер поддерживает подмножество и **честно об этом сообщает**, а не
  рисует молча иначе.
