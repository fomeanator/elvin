# Пакеты .lvns — библиотеки механик с версиями

Библиотека .lvns (боёвка, экономика, UI-обвязка) распространяется **пакетом**:
каталог со скриптами, ассетами и манифестом. Скачивание и проверка — только
`lvnconv deps …`; **`convert` в сеть не ходит никогда** и собирается оффлайн
из vendor-каталога. Компилятор знает про пакеты ровно одно: путь include,
начинающийся с `@`, ищется в `lvns_packages/` вверх по дереву от
подключающего файла.

```
include "@fomean/lvn-duel/duel.lvns"     // файл пакета
include "механики.lvns"                  // обычный сосед — как раньше
```

## Устройство пакета

```
lvn-duel/
  lvns.package.json    ← имя, версия, exports
  duel.lvns            ← скрипты (могут include'ить друг друга относительно)
  assets/…             ← спрайты; deps sync копирует их в
                         <content_dir>/packages/<имя-без-скоупа>/…
```

`lvns.package.json` пакета:

```json
{
  "name": "@fomean/lvn-duel",      // обязателен, "@scope/pkg", строчные
  "version": "0.1.0",
  "license": "MIT",
  "min_engine": "0",
  "exports": ["duel.lvns"]         // что можно include'ить снаружи
}
```

Скрипты пакета ссылаются на свои ассеты ТОЛЬКО как
`/content/packages/<имя>/…` — тогда пакет работает в любой игре без правок.
Рантайм никогда не качает ассеты с GitHub: они уже в контенте игры.

## Проект-потребитель

`lvns.package.json` в корне проекта:

```json
{
  "content_dir": "server/content",
  "dependencies": {
    "@fomean/lvn-duel": "github:fomean/lvn-duel@v0.1.0",
    "@dev/local":       "file:packages/local"
  }
}
```

Команды:

```sh
lvnconv deps sync      # привести lvns_packages/ к lock-файлу (оффлайн, если всё на месте)
lvnconv deps update    # пере-разрешить манифест, переписать lock
lvnconv deps add "@fomean/lvn-duel" "github:fomean/lvn-duel@v0.1.0"
lvnconv deps list      # что зафиксировано
```

## Правила воспроизводимости (это не опции)

- **`lvns.lock`** хранит ref, SHA коммита, SHA-256 тарболла и SHA-256 каждого
  файла. Одинаковый lock → байт-в-байт одинаковый vendor. Коммить в репозиторий.
- **Mutable-ссылки запрещены**: `github:…@main` — ошибка сразу. Тег или полный
  SHA. Передвинутый тег ловится несовпадением хэша тарболла — это жёсткая
  ошибка, а «обновиться» можно только явным `deps update`.
- **`file:`-ссылки — режим разработки** пакета по соседству: без сети и без
  пиннинга, `deps list` помечает их `⚠ mutable`. В прод-lock им не место.
- Тарболл: только обычные файлы, никаких симлинков и `..`; предел 64 МБ /
  4096 файлов. Циклы зависимостей — ошибка с цепочкой имён.
- `github:owner/repo@tag#subdir` — пакет в подкаталоге монорепы.

## Сервер (студия)

Публикация файла пакета — тем же `POST /v1/admin/agent/publish`, но с полным
путём: `{"path": "@fomean/lvn-duel/duel.lvns", "lvns": …}` → файл ложится в
`scripts/lvns_packages/…`, и правка пакета пересобирает все главы, которые
тянут его напрямую или через другой пакет (транзитивно, как у плоских общих
файлов). Ассеты пакета — обычный `PUT /v1/admin/assets/packages/<имя>/…`.

Совместимость со старыми серверами (без `@`-путей): публиковать файл пакета
под плоским именем (`"path": "duel.lvns"`) и расплющивать include в главе —
ровно это делает текущий деплой lvn-duel в студию племянников.

## Как опубликовать свой пакет

Разработка идёт в монорепе, публикация — автоматическая, как у UPM-пакетов:

1. Заводишь `packages/<имя-репо>/` с `lvns.package.json` (поле `name` —
   `@scope/pkg`), скриптами и `assets/`.
2. Создаёшь публичный репозиторий `fomeanator/<имя-репо>` (одноимённый каталогу).
3. Ставишь версионный тег в монорепе — `.github/workflows/mirror-packages.yml`
   сплитит историю каталога и пушит её в зеркало вместе с тегом. Список
   пакетов НЕ захардкожен: новый каталог публикуется сам.
4. Потребители ставят `github:fomeanator/<имя-репо>@<тег>`.

Зеркало read-only: правки делаются в монорепе, иначе следующий сплит их
затрёт.
