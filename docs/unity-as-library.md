# Движок внутри чужого приложения (Unity as a Library)

Обычно Elvin — это самостоятельное приложение: сборка выдаёт APK, игрок ставит
его и играет. Но движок умеет и второй режим — быть **экраном внутри уже
существующего продукта**. Unity собирается модулем, хост монтирует его как свой
экран, и для игрока это одна программа.

Когда это нужно: у продукта уже есть витрина, вход, платежи, и переписывать их
на Unity бессмысленно. Тогда хост остаётся хостом, а движок отвечает только за
сцену.

## Что происходит на стороне движка

```sh
LVN_BUILD_OUT=/tmp/lvn-unity-lib \
Unity -batchmode -nographics -projectPath <экспортированный проект> \
      -buildTarget Android \
      -executeMethod Lvn.EditorTools.CliBuild.AndroidLibrary \
      -quit -logFile build.log
```

На выходе — Gradle-проект, в нём модуль `unityLibrary`. Всё остальное
(сцена, графическое API, штамп версии) идёт тем же путём, что и обычный APK:
библиотека не отличается от игры ничем, кроме упаковки.

⚠️ Флаг экспорта — состояние **редактора**, оно переживает запуски. Поэтому
`CliBuild.Android()` явно его снимает; иначе после одной библиотечной сборки
конвейер молча выдавал бы Gradle-проекты вместо пакетов.

### Сколько это весит

Экспорт занимает около 600 МБ, но в приложение едет не всё: львиная доля —
исходники IL2CPP, нужные только для компиляции. В APK попадают:

| часть | размер |
|---|---|
| `unityLibrary/src/main/assets` | ~26 МБ |
| `unityLibrary/src/main/jniLibs` (arm64-v8a) | ~27 МБ |
| итого к приложению | **~53 МБ** до сжатия |

Контент новелл сюда не входит — клиент стриминговый и тянет главы с сервера.

## Как подключается на стороне хоста (Android)

```gradle
// settings.gradle
include ':unityLibrary'
project(':unityLibrary').projectDir = new File(rootDir, 'unityLibrary')

// build.gradle (корневой) — Unity кладёт свои .aar рядом с модулем
allprojects { repositories { flatDir { dirs "${rootProject.projectDir}/unityLibrary/libs" } } }

// app/build.gradle
implementation project(':unityLibrary')
```

Модуль подключается **исходником, а не .aar**: тогда пересборка движка видна
сразу, без ручной перепаковки.

## Разговор между хостом и движком

Канал — `LvnHostBridge` (пакет `com.lvn.engine.shell`).

**Внутрь** нативная сторона умеет дотянуться единственным способом —
`UnitySendMessage(объект, метод, строка)`. Поэтому мост живёт на объекте с
фиксированным именем:

| | значение |
|---|---|
| объект | `LvnHostBridge` |
| метод | `OnHostMessage` |

Имена — часть договора: переименование ломает мост **молча**, без ошибки
сборки.

**Наружу** движок ничего не знает о хосте. Отправка объявлена делегатом,
который хост подключает у себя:

```csharp
LvnHostBridge.Send = json => UnityMessageManager.Instance.SendMessageToRN(json);
```

Почему не позвать `UnityMessageManager` напрямую: тогда публичный движок
перестанет компилироваться без пакета-обёртки, нужной одному потребителю. Тот
же приём, что и со Spine — мы объявляем точку, подключает её хост.

### Сообщения

Движок шлёт:

```json
{"type": "chapter_started",  "title": "cold", "chapter": "ch01"}
{"type": "chapter_finished", "title": "cold", "chapter": "ch01"}
{"type": "pong"}
```

Хост шлёт `{"type": "ping"}` (проверка канала) и любые свои команды —
неизвестный движку тип уходит в `LvnHostBridge.Command`, где его разбирает
игра. Движок сознательно не знает про валюту, профиль и покупки хоста.

## Три ограничения, которые надо знать заранее

1. **Unity в приложении один и экран один.** Второй экран смонтировать нельзя:
   это один процесс с одной поверхностью отрисовки. Значит, движок открывается
   на весь экран, а не карточкой в списке.
2. **Выгрузка неполная.** После ухода с экрана Unity держит часть памяти до
   конца процесса. На практике терпимо, но «закрыл игру — память вернулась»
   не произойдёт.
3. **Managed Expo придётся раскрыть.** Модуль нативный, чистый managed его не
   примет: нужен `expo prebuild`. Обратной дороги в чистый managed нет.

## Пример хоста на React Native

Экран-образец: `UnityGameScreen.js` в прототипе AppTok. Он показывает весь
цикл — монтирование `<UnityView>`, опрос `ping` до ответа, передача сессии
игроку, отчёт о пройденной главе в бэкенд хоста и перехват аппаратной кнопки
«назад» (Unity забирает фокус, и обычная навигация до него не доходит).
