# Скины: одно место настройки

Документ к TR-114 (Илья 15.09.2026: «любой контент — скин; единообразная
система, настраиваемая через админку; фул настройка в одном месте»).

## Что такое скин

Всё, что можно надеть, показать или включить и что лежит в инвентаре
кошелька по ключу (sku): наряды героев, фоны меню, аватарки; дальше —
рамки диалога, темы, шрифты, музыка. Одна запись на вещь:

| поле | смысл |
|---|---|
| `sku` | ключ инвентаря — как уже живёт в кошельках: `wardrobe:<герой>:<ось>:<значение>`, `wardrobe:menu:backdrop:<id>`, `avatar.<id>` |
| `kind` | домен: `wardrobe`, `backdrop`, `avatar` |
| `name`, `art`, `preview` | подпись, полный арт, мини для витрины. У аватарки имя тоже едет в манифест (`avatars[].name`) и подписывает плитку в выборе лица; пусто — плитка без подписи, id не показывается |
| `rarity` | ступень; цвет — у палитры ступеней (`rarity_colors`), не у скина |
| `price`, `currency` | цена: покупка в гардеробе, если `buy`; продажа копии из крутки — всегда |
| `buy` | продаётся в гардеробе; `gacha` без `buy` = «только из крутки» (флаг `gacha` у наряда в манифесте) |
| `gacha`, `gacha_weight` | выпадает в крутках; свой вес, иначе вес ступени (`rarity_weights`) |
| `description` | описание — в подробностях плитки (долгое нажатие) |
| `sell_price` | за сколько продаётся копия из крутки и новый скин по кнопке «Продать» в церемонии (`/v1/gacha/sell`); 0 — за цену скина |
| `hidden` | скрыт: не показывается в гардеробе, среди фонов, аватарок и в крутке; у игроков в инвентаре остаётся |
| `order` | порядок показа внутри оси или домена; 0 — как в манифесте |
| `tags` | метки через запятую — поиск в админке, будущие наборы |

## Где лежит и как правится

`skins.json` в каталоге контента, рядом с `gacha.json`. Правится в админке:
Экономика → «Скины — одно место настройки». Сохранение применяется само:
сервер раскладывает цены, ступени, арт, названия и флаг «только из
крутки» по `manifest.json`, а призы и веса ступеней — по `gacha.json`
(с историей и откатом, как у остальных конфигов). Клиент пока читает
манифест, как читал, — вид не меняется; сборка не нужна.

Ручки сервера: `POST /v1/admin/skins/collect` — собрать или досыпать
каталог из манифеста и барабана (правленые записи не трогает);
`POST /v1/admin/skins/apply` — применить; `GET /v1/skins` — каталог.

Новый скин: либо форма «Новый» во вкладке (аватарка и фон заводятся в
манифесте при применении сами; наряд — если у героя уже есть такая ось),
либо добавить в манифест и нажать «Собрать из манифеста».

## Наборы круток (кейсы)

Крутки — наборами (Илья и партнёр 15.09: «в крутке выбрать, какой кейс
крутить; пока один, потом второй»). Набор живёт в том же `skins.json`
(`cases`): id, имя, описание, обложка, цена и валюта крутки, порядок,
«скрыт», при желании свои сектора. Приз попадает в набор, если тот назван у
скина в `cases`; скин с `gacha` и пустым `cases` — в первом наборе.
Применение раскладывает наборы в `gacha.json` (`cases`), верхний уровень
файла — первый набор, чтобы старые клиенты жили как жили. Сервер:
`GET /v1/gacha?case=id`, `POST /v1/gacha/spin` с `{"case": id}`, в статусе
`cases` — сводка для выбора. В игре ряд наборов над лентой показывается,
когда наборов больше одного; последний выбранный помнится.

### Живой фон (spine) — TR-132, TR-133

**Смена фона плавная по умолчанию (18.09).** Картинка и живая сцена меняются
одним правилом — растворением прежнего кадра за `ui.stage.bg_fade` (0,35 с);
живая текстура растворяется по снимку кадра, чтобы снесённая парком сцена
не оборвала переход. Ноль — мгновенно (кадр 3D-набора).

**Спайн-сцена — одна сущность движка (17.09).** Сцена = скелет + её
нарисованный задник + посадка + проигрыш, и собирается она ОДНИМ входом —
`LvnSpineRef.Resolve(каталог, ключ-или-адрес, bg, play, fit)`. Задник, если его
не назвали явно, берётся из реестра `LvnSpineBackdrops`, выученного из
манифеста (`Learn`: фоны меню с полем `spine` → их `url`). Этим
входом пользуются карточка новеллы, полотно меню, глава (`bg spine=`), магазин
и прогрев — поэтому сцена не может «потерять фон» в одном месте и сохранить в
другом («у агентства нет фона, только эффект» — Илья 17.09). Сцена по адресу
без посадки садится `cover`; фигура из каталога сохраняет свою.


У фона меню (`kind: backdrop`) есть поле `spine` — папка спайн-сцены
(`/content/spine/имя/` → `имя.json` + `имя.atlas.txt` + страницы). Раскладка
переносит его в `ui.browse.canvas_options[].spine`, а меню шлёт его в команде
фона `bg` полем `spine`: сцена ставит скелет во весь кадр (`fit: cover`) позади
героини, `art` (jpg) остаётся обложкой плитки, подложкой под спайном и кадром под
переезд между комнатами. Живой фон по умолчанию, когда игрок ничего не купил, —
`ui.browse.canvas_spine`. Поле `still` — «без увеличения»: полотно стоит 1:1, не панорамирует между
комнатами, живой фон ставится без въезда; пусто — спайн неподвижен, картинка
едет как раньше (Илья 16.09: «выбор — есть увеличение фона или нет», колонка
«Увелич.» в админке). Покупка, примерка и надевание — как у любого фона (Илья
16.09: «в гардеробе спайн-фон можно купить»). У новеллы в меню свой живой постер:
`titles[].spine` (папка или ключ `sprites`) — вместо одной Ноэль на всех карточках.

## Валюты — тоже здесь (TR-117)

`currencies` в `skins.json` — как валюта выглядит по всему приложению:

| Поле | Смысл |
|---|---|
| `name`, `unit` | «Кристаллы», «кристаллов» — имя и форма при сумме («1 200 кристаллов») |
| `color` | цвет вектора и суммы («#f0c860») |
| `icon` | векторный значок движка на случай, когда картинки нет (Gem, Energy, Coin, Key, Heart) |
| `image` | картинка валюты — адрес в контенте; одна на шапку, ценники, плитки, крутки |

Применение пишет облик в `ui.currency_look` и картинку в
`ui.browse.currency_icons` манифеста (старые сборки читают только её).
Клиент держит один реестр (`LvnPriceTag`): значок всюду просят у него —
картинка, если есть, иначе вектор. Раньше картинка жила в четырёх картах
манифеста, и половина экранов рисовала вектор-заглушку («два значка на одну
сущность» — Илья 15.09).
