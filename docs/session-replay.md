# Смотреть чужой проход

Отчёты отвечают «где теряем». Этот документ — про то, чтобы **увидеть один
конкретный проход** и понять, почему потеряли именно там.

## Что уже есть

Агрегатная половина сделана и работает по авторским меткам, а не по адресам
компилятора:

| Модуль | Отвечает на вопрос |
|---|---|
| `analytics_slides.go` | докуда дочитывают внутри главы |
| `analytics_exits.go` | где бросают и **что было на экране** |
| `analytics_marks.go` | воронка по значимым местам, названным автором |
| `analytics_rollup.go` | свёртка, чтобы отчёт не читал сырой журнал |
| `analytics_experiment.go` | результат по вариантам A/B |

Не хватает не отчёта. Не хватает возможности сказать: «покажи мне тот сеанс,
где ушли на сцене знакомства» — и посмотреть его.

## Почему нам не нужно видео

Вебвизор пишет пиксели и мутации DOM, потому что не знает, что происходит
внутри чужого сайта. Мы знаем — и у новеллы есть свойство, которого нет у сайта:

> Скрипт + версия контента + путь выборов + состояние генератора случайных
> дают **тот же проход, кадр в кадр**.

Это не предположение. Детерминизм закреплён тестами: `ASeededStreamReplaysExactly`,
`AnotherSessionRestoringTheSaveGetsTheSameRoll`, `ReloadReplaysTheSameRollInsteadOfReRollingIt`.
Состояние генератора уже ездит в сейве (`LvnSnapshot.RngState`), а восстановление
кадра прокруткой истории уже написано (`LvnPlayer.ReplayPath`) — для сейвов.

Отсюда: **запись сеанса — не видео, а программа**.

```
скрипт + версия · путь выборов · зерно · тайминги по тактам · точка ухода
```

Полкилобайта против мегабайтов. И воспроизведение ТОЧНОЕ: мы проигрываем ту же
программу, а не похожую картинку. Вебвизор так не умеет — он показывает
реконструкцию.

## Тайминги — это и есть ответ

«Где ушёл» знает и текущий отчёт. Запись даёт то, чего он не знает:

- **где завис** — такт держали втрое дольше соседних: непонятно написано или
  ждали загрузки;
- **где перечитывал** — вернулся назад по истории;
- **где пролистывал не глядя** — секунда на реплику, которую не прочесть за
  секунду: сцена не держит;
- **где бросил на середине реплики** — не «на команде 137», а посреди фразы.

Первое и последнее — прямые деньги: одно чинится текстом, другое загрузкой.

## Формат записи

Пишется тем же путём, что и остальные события (`LvnAnalytics.Track`), но одной
записью на сеанс, а не событием на такт: журнал не должен расти от того, что мы
стали внимательнее.

```
session   идентификатор сеанса
script    какая глава и КАКОЙ ВЕРСИИ (иначе проигрываем не тот текст)
seed      состояние генератора на входе
path      индексы выборов по порядку
beats     тайминги: такт → миллисекунды (упаковкой, не списком объектов)
exit      где и почему кончилось: дочитал / ушёл / упал / кончилась энергия
```

**Версия контента обязательна.** Проход, записанный до правки главы, проигрывать
по новому тексту нельзя — получится ложь, которая выглядит убедительно. Если
версии нет, воспроизведение обязано отказаться и сказать почему (правило то же,
что у `ResumeSaysTheChapterChangedInsteadOfGuessing`).

## Порядок работ

1. **Запись.** Формат + отправка одной записью в конце сеанса и при обрыве.
2. **Хранение.** Тот же JSONL, что и события. ClickHouse — не сейчас: порог ≈
   миллион событий в месяц, сейчас 210 за 30 дней. Число записано, чтобы
   разговор не повторялся.
3. **Воспроизведение.** Проиграть запись движком и убедиться, что кадр в кадр
   совпал с исходным проходом. **Это и есть главная проверка замысла**: без неё
   всё остальное — красивая гипотеза.
4. **Свод.** Сложить тайминги по всем сеансам: где массово зависают, где массово
   пролистывают. Отчёт «места, где скучно» — то, чего нет ни у кого.
5. **Смотрелка.** Список сеансов с фильтром по точке ухода; выбрал — проигралось.

Порядок не переставлять: пункт 3 либо подтверждает замысел, либо хоронит его, и
делать 4–5 до него — строить на непроверенном.

## Чего это стоит соседям

Ren'Py, Naninovel, Ink, Twine записать проход так не могут: у них нет ни
серверной части, ни версионированного контента, ни гарантии детерминизма поверх
авторского кода на Python. Их путь — писать видео с экрана, то есть мегабайты и
согласие игрока. Наш — полкилобайта и точность.
