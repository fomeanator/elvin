# Конвейер выпуска: dev → prod

Заведён 14.09.2026 после дня, когда «две версии игры», «где мои правки» и
«что в этой сборке» стоили больше, чем сама работа. Причина у всех трёх одна:
APK собирался из **рабочего дерева**, в котором лежало незакоммиченное трёх
человек, и по сборке нельзя было назвать коммит.

## Правила

1. **Две ветки.** `dev` — интеграция, `main` — прод. Каждый (кодекс, Ваня,
   Клод) работает в **своей** ветке и вливает её в `dev`. В `main` попадает
   только `dev` целиком, после того как dev-сборку потыкали.
2. **Незакоммиченного в общем дереве не бывает.** Задача сделана — коммит в
   свою ветку. Правки, которые лежат в дереве без коммита, в сборку не
   попадают и при следующем слиянии теряются — это не угроза, а следствие
   пункта 3.
3. **Сборка — только из коммита на origin**, в отдельном дереве
   (`~/ominis/builds/release-<канал>`), скриптом `qa/release.sh`. Проект
   сборки один; на время сборки его пакеты указывают на дерево релиза и
   возвращаются после. Клонов проекта не бывает. Всё продуктовое — сервер,
   путь к проекту сборки, адрес выкладки, префикс имён файлов — живёт вне
   репозитория (он публичный): `~/.config/lvn/release.env`.
4. **Две сборки рядом на одном телефоне.** Dev — пакет `<пакет>.dev`,
   ярлык «<Имя> Dev»; prod — как есть. Хэш коммита и канал зашиты в
   сборку: Настройки → Версия (`20260914.1815 · dev e18dc31d`) и строка
   `[lvn-build]` в логе устройства, который уезжает на сервер.
5. **Проверки перед каждой сборкой** одни и те же: компиляция C# (Roslyn),
   Go-стражи (ноль падений), стенд утечек (репозиторий публичный). Красное —
   сборки нет.

## Команды

```sh
SSHPASS='<пароль сервера>' qa/release.sh dev    # origin/dev  → <адрес выкладки>/<префикс>-dev-<штамп>.apk (+ dev-latest)
SSHPASS='<пароль сервера>' qa/release.sh prod   # origin/main → <адрес выкладки>/<префикс>-<штамп>.apk     (+ prod-latest)
```

Журнал выпусков — `~/ominis/builds/releases.log`: дата, канал, коммит, файл,
пакет, sha256. Логи проверок и сборки лежат рядом с APK под тем же именем.

## Цикл

```
ветка задачи ──merge──▶ dev ──release.sh dev──▶ <префикс>-dev-….apk ──потыкали──▶ main ──release.sh prod──▶ <префикс>-….apk
```

Слияние `dev → main` — обычный `git merge --ff-only dev` (dev всегда впереди
main, конфликтов там не бывает по построению). Откат прода — `release.sh prod`
на прежнем коммите `main` (сдвинуть ветку назад и выпустить).

## Что считать поломкой конвейера

- В дереве релиза появилось незакоммиченное (скрипт остановится).
- Пакеты проекта сборки остались перенаправленными после падения скрипта —
  `Packages/manifest.json.release-bak` рядом, вернуть руками.
- В настройках сборки не видно хэша — значит собрали не скриптом.

## Сниппет в мессенджере

По ссылке на `.apk` бот-превью (Telegram, WhatsApp…) получает карточку: в
тексте — короткий **путь проверки**, на картинке — список решённого. Путь
собирается из строк `Проверить: …` в телах коммитов с прошлого выпуска
канала, список — из тем коммитов (служебные `docs/chore/test` опускаются).
Для ручного текста — файл заметок: `RELEASE_NOTES=<файл> qa/release.sh prod`,
где строки `Проверить: …` идут в текст, остальные — в список.

## Задачи

Любая работа начинается с задачи в трекере и отчитывается в ней: что
изменилось, в какой сборке, как проверить. Коллеги видят ход дела без чтения
кода и чата — иначе получается чёрный ящик.
