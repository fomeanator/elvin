# Онбординг: внешний вид оболочки (главная, магазин, профиль)

Для нового человека в команде. Задача — **улучшать внешний вид** трёх экранов.
Сервер, API и контент трогать не нужно: они уже работают, ты подключаешься к
готовому и правишь только то, что видно.

---

## 1. Что поднять — двадцать минут

### Шаг 1. Клонировать

```sh
git clone https://github.com/fomeanator/elvin.git
cd elvin
```

### Шаг 2. Указать сервер

Открой `ui-lab/Assets/UiLab/Boot.cs` и поставь в `ServerUrl` адрес, который дал
Илья:

```csharp
public const string ServerUrl = "https://…";   // адрес от Ильи
```

Это всё. Приедут живые новеллы, настоящий арт, настоящие цены — то же самое,
что видит игрок. Ничего поднимать локально не надо.

<details>
<summary>Если понадобится свой сервер (не нужен для этих задач)</summary>

```sh
tools/dev/serve.sh          # демо-контент репозитория на 127.0.0.1:8077
```
и вернуть `ServerUrl` на `http://127.0.0.1:8077`. Нужен, только когда правишь
контент, а не вид: панель авторов там же, на `/panel/`.
</details>

### Шаг 3. Открыть в Unity

**Unity 6000.4.5f1** → Open → папка **`ui-lab/`** → Play.

Сцену собирать не надо: камера, EventSystem и приложение поднимаются сами
(`ui-lab/Assets/UiLab/Boot.cs`). Первый импорт — несколько минут, дальше секунды.

> **Не открывай `sandbox/`.** Это моя рабочая песочница: её манифест ссылается
> на пакеты Spine по абсолютному пути с моей машины (у тебя проект просто не
> откроется), и в ней 600 МБ трёхмерного арта, к интерфейсу отношения не
> имеющего. `ui-lab/` — то же приложение без всего этого.

### Шаг 4. Увидеть три своих экрана

После Play: хаб (**главная**) открывается сам. Оттуда:

| Экран | Как попасть | Файлы |
|---|---|---|
| **Главная** (хаб) | сразу после запуска | `BrowseHub.cs`, `BrowseHub.Cards.cs`, `BrowseHub.Feed.cs`, `BrowseHub.Nav.cs`, `BrowseHub.Bits.cs` |
| **Магазин** | плюсик у валюты в верхней панели, либо нижнее меню | `PackShopScreen.cs`, `PackShopScreen.Cards.cs` |
| **Профиль** | нижнее меню → профиль | `ProfileScreen.cs`, `ProfileScreen.Account.cs` |

Все — в `unity/Packages/com.lvn.engine.shell/Runtime/`.

## 3. Как менять вид правильно

Три правила. Их проверяют на ревью, и они же экономят время.

### 3.1 Ни одного названия игры в коде

Названия, обложки, цены, валюты, палитра приходят с сервера (`ui.*` в
манифесте). Один и тот же код обслуживает разные продукты. Захардкодил
название — сломал это молча.

### 3.2 Цвет, отступ, радиус, кегль — из токенов

```csharp
// так:
row.style.backgroundColor = LvnTokens.Surface;
LvnAir.PadX(row, LvnTokens.Space3);
LvnChrome.Round(row, LvnTokens.RadiusSm);

// не так:
row.style.backgroundColor = new Color(0.14f, 0.10f, 0.14f);
row.style.paddingLeft = 12;
```

Токены живут в `LvnTokens` и берут значения у темы, которая приходит с сервера.
Число на глаз выпадает из темы: при смене оформления твой элемент останется
прежним, а соседние поменяются.

**Готовые роли — берите их, а не собирайте заново:**

| Хочу | Зовите |
|---|---|
| главная кнопка экрана | `LvnStyler.Primary(el)` |
| второстепенная | `LvnStyler.Quiet(el)` |
| ярлык (цена, жанр, счётчик) | `LvnStyler.Chip(el, заливка)` |
| строка списка | `LvnStyler.ListRow(el)` |
| строка-карточка (с кромкой) | `LvnStyler.CardRow(el)` |
| всплывающая панель | `LvnStyler.Panel(el, заливка)` |
| квадратная кнопка-значок | `LvnStyler.IconSlot(el, размер)` |
| скруглить / кромка / рамка | `LvnChrome.Round` / `.Edge` / `.Border` |
| внутренние отступы | `LvnAir.Pad` / `.PadX` / `.PadY` |
| перенос строки | `LvnFlow.Wrap(el, выравнивание)` |
| значок | `LvnIcons.Make(LvnIcon.X, размер, цвет)` |
| цена со значком валюты | `LvnPriceTag.Tag(валюта, сумма, ряд)` |

Полный список домов с объяснением, зачем каждый заведён, —
[`where-things-live.md`](where-things-live.md). Если работа не ложится ни в
один — это либо новый дом, либо она стоит не на своём этаже; и то и другое
стоит обсудить, а не решать молча.

### 3.3 Экран не ходит в сервер

Экран объявляет колбэк (`OnBuy`, `OnPlay`), а связывает его `NovelShell`. Так
экран можно смотреть отдельно и не бояться сломать экономику.

## 5. Правку не видно на экране — три причины, в этом порядке

1. **Unity не пересобирает C# во время Play.** Нужен Stop → Play. Проверка за
   пять секунд: экран настроек, строка версии — рядом стоит время сборки
   движка. Оно старше твоей правки — ты смотришь на старый код.
2. **Сервер отдаёт не то.** Оформление приходит из манифеста, а не из кода.
   Проверка: открой в браузере `<адрес>/v1/content/manifest`.
3. **Поле есть, читателя нет.** Настройка в манифесте без места чтения в коде —
   молчаливый no-op: в файле написано, на экране ничего.

# ЗАДАЧИ

Все три — про внешний вид. Логику менять не нужно; если для вида понадобилось
трогать поведение, это повод спросить, а не сделать.

## Задача 1. Главная (хаб) — `BrowseHub`

Первый экран игры: заголовок, подборки, карточки новелл, нижняя навигация.

**Что улучшить:**
- **Карточка новеллы** — сейчас это обложка с подписью. Дать ей вес: рамку по
  теме, тень/свечение под активной, читаемую плашку под текстом (сейчас текст
  местами ложится прямо на арт и теряется на светлых обложках).
- **Ритм сетки.** Отступы между карточками и до краёв подобраны по месту.
  Свести к шкале токенов и одинаковому ритму по всем подборкам.
- **Заголовок подборки** — сейчас просто текст. Сделать различимым: кегль,
  разрядка, при необходимости — тонкая линия или счётчик.
- **Пустое состояние.** Подборка без карточек сейчас исчезает целиком. Игрок не
  понимает, что раздел есть.
- **Появление.** Карточки приезжают со сдвигом — проверить, что это читается
  как задумано на медленном устройстве, а не как подтормаживание.

## Задача 2. Магазин — `PackShopScreen`

Экран покупки валюты: вкладки по валютам, карточки паков, ленты-бейджи.

**Что улучшить:**
- **Иерархия карточек.** Сейчас все паки выглядят одинаково весомо. Выделить
  рекомендуемый: размером, фоном, свечением — так, чтобы взгляд падал на него
  первым. Ленты `Popular` / `Value` / `BestPrice` уже есть, но не различимы.
- **Цена — главный элемент карточки.** Сейчас она соседствует с составом
  набора и теряется. Кегль, вес, положение.
- **Состав набора** («550 кристаллов · 5 энергии») — чипами по ролям валют, с
  правильными значками (`LvnPriceTag` уже умеет).
- **Кнопка покупки** — четыре состояния должны читаться: готова, идёт, удалась,
  отказ. Сейчас различимы два.
- **Вкладки валют** — сейчас обычные кнопки; активную видно слабо.

## Задача 3. Профиль — `ProfileScreen`

Карточка личности, статы плитками, достижения, отношения.

**Что улучшить:**
- **Карточка личности** — сейчас имя и ID текстом. Она сверстана под аватар,
  а аватара нет. Спроси у Ильи, откуда его брать (готовый набор или буква
  имени), и сделай.
- **Плитки статов** — выровнять ритм, дать числам вес, подписям — тишину.
- **Достижения.** Пустой список сейчас прячет секцию целиком: игрок не знает,
  что достижения вообще есть. Показать сетку с закрытыми значками.
- **Отношения** — карточки персонажей с прогрессом. Проверить, как выглядит
  один персонаж и как двенадцать.
- **Подвал с UID** — служебный, но занимает место наравне с содержательным.
  Приглушить.

## Что спросить у Ильи до начала

1. Аватар в профиле — откуда: готовый набор, буква имени, загрузка?
2. Показывать ли кошелёк в профиле — сейчас балансы живут в верхней панели, а
   поле `Wallet` в профиле заполняется и не показывается.
3. Какие ленты-бейджи в магазине оставить и что считать «рекомендуемым паком».

Это решения про продукт, а не про код: они за владельцем.
