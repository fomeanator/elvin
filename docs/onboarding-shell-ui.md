# Онбординг: магазин и профиль (оболочка LVN)

Документ для нового человека в команде. Цель — поднять проект локально за
двадцать минут и взять две задачи: **главный экран покупки** и **профиль**.

Ничего про внутренности плеера новелл знать не нужно: оболочка отделена от него
и правится независимо.

---

## 1. Доступы

| Что | Где | Кто выдаёт |
|---|---|---|
| Код движка и оболочки | `github.com/fomeanator/elvin`, ветка `main` | публичный, клонируется без доступа |
| Задачи | YouTrack `111-88-74-156.sslip.io` | Илья |
| Продуктовый репозиторий | GitLab `time-romance/*` | Илья |

Работа идёт **в репозитории движка**: экраны магазина и профиля живут в
`unity/Packages/com.lvn.engine.shell/Runtime/`. Продуктовый репозиторий нужен
только чтобы посмотреть живой контент; править его для этих задач не надо.

## 2. Поднять за двадцать минут

```sh
git clone https://github.com/fomeanator/elvin.git
cd elvin

# 1) сервер с демо-контентом (отдельное окно, не закрывать)
tools/dev/serve.sh

# 2) Unity 6000.4.x → открыть папку sandbox/ → Play
```

`sandbox/Assets/Sandbox/Boot.cs` сам поднимает камеру, EventSystem и `NovelApp`,
указывающий на `127.0.0.1:8078`. Сцену собирать руками не нужно.

Проверка, что живо: в приложении открывается хаб, из него — магазин и профиль.
Панель авторов (правка контента в браузере) — на том же адресе, `/panel/`.

### Правку не видно на экране — три причины, в этом порядке

1. **Unity не пересобирает C# во время Play.** Нужен Stop → Play. Проверка за
   пять секунд: экран настроек, строка версии — рядом стоит время сборки
   движка. Оно старше твоей правки — ты смотришь на старый код.
2. **Сервер отдаёт не тот контент.** Оформление приходит из манифеста, а не из
   кода: `curl -s 127.0.0.1:8078/v1/content/manifest | head -c 200`.
3. **Поле есть, читателя нет.** Настройка в манифесте без места чтения в коде —
   молчаливый no-op.

## 3. Три правила, которые проверяются на ревью

1. **Ни одного названия игры в коде оболочки.** Названия, обложки, цены,
   валюты, палитра приходят из манифеста (`ui.*`). Один и тот же код обслуживает
   разные продукты; хардкод продукта ломает это молча.
2. **Цвет, радиус, отступ, кегль — из токенов темы** (`LvnTokens`), а не числом
   на глаз. Роль элемента ставит `LvnStyler` (`Primary`, `Quiet`, `Chip`,
   `Panel`, `ListRow`, `CardRow`), огранку — `LvnChrome`, воздух — `LvnAir`.
   Прямое число в стиле — повод объяснить в комментарии, почему именно оно.
3. **Экран не ходит в сервер и не знает про кошелёк.** Он объявляет колбэки
   (`OnBuy`, `OnPlay`, `OnStore`), а связывает их `NovelShell`/`NovelApp`.

Эталоны размеров и отступов — [`visual-standards.md`](visual-standards.md),
палитра и фактуры — [`ui-panel-set-brief.md`](ui-panel-set-brief.md), карта
домов (что где живёт) — [`where-things-live.md`](where-things-live.md), общий
гайд по оболочке — [`ui-development.md`](ui-development.md).

## 4. Как сдавать

```sh
qa/compile.sh     # собирает 8 сборок без Unity, ~20 с — гонять после каждой правки
qa/run-all.sh     # полный набор: EditMode + PlayMode + Go + node, ~10 мин
```

Ветка от `main`, имя `feat/shop-…` или `feat/profile-…`. В PR — скриншот «до/
после» на 1080×1920. Красный `run-all` не мержится.

# ЗАДАЧА 1. Главный экран покупки (`PackShopScreen`)

**Файлы:** `PackShopScreen.cs`, `PackShopScreen.Cards.cs`.

**Что есть сейчас.** Экран работает и самодостаточен: строит вкладки из живого
каталога `/v1/iap/catalog`, а если каталога нет — показывает **зашитые
демо-паки**, чтобы экран не выглядел пустым. Кнопка покупки при этом гоняет
безобидное «…» → «✓», а не настоящую оплату. Есть ленты-бейджи
(`Popular` / `Value` / `BestPrice`) и состав набора чипами.

**Что сделать.**

1. **Разделить «нет каталога» и «каталог пуст».** Сейчас оба случая дают
   демо-паки. Первое — беда связи, о ней надо сказать; второе — законное
   состояние (в этой сборке покупок нет), и тогда экран не должен открываться
   вовсе. Демо-паки оставить только для режима разработки.
2. **Состояние покупки довести до конца.** Кнопка обязана иметь четыре вида:
   готова, идёт, удалась, отказ с причиной. Отказ показывать словом из
   `ui.words`, а не кодом ошибки. Повторное нажатие во время «идёт» —
   запрещено (сейчас защиты нет).
3. **Восстановление покупок** — отдельная строка внизу списка. Обязательна для
   App Store; сейчас её нет.
4. **Цена всегда из каталога.** Валюта, разряды и знак приходят от магазина
   платформы; форматирование — через `LvnPriceTag`, а не `ToString()`.

**Готово, когда:** без сети экран говорит про сеть, а не показывает выдуманные
паки; двойное нажатие не создаёт двух покупок; отказ читается словами; есть
восстановление; на 1080×1920 и на iPhone SE ничего не переполняется.

**Спросить у Ильи до начала:** нужен ли экран, когда покупок нет вовсе; какие
ленты-бейджи оставить.

# ЗАДАЧА 2. Профиль (`ProfileScreen`, `ProfileScreen.Account.cs`)

**Что есть сейчас.** Шесть секций: карточка личности, плитки статов,
достижения, отношения, кошелёк, подвал с UID. Есть режим `Minimal` (профиль =
имя + ID, без уровня и XP) — им пользуется текущий продукт.

**Что сделать.**

1. **Кошелёк на экране.** Поле `Wallet` объявлено, заполняется и **не
   показывается**: балансы живут в шапке. Решить с Ильёй — либо показать
   секцию, либо убрать поле; сейчас это мёртвый код, который выглядит живым.
2. **Аватар.** Сейчас его нет вовсе, а карточка личности под него сверстана.
   Источник — из манифеста (`ui.profile.avatar_*`), выбор — из готового набора,
   не загрузка файла.
3. **Достижения: пустое состояние.** Пустой список прячет секцию целиком, и
   игрок не знает, что достижения вообще есть. Показать сетку с закрытыми
   значками.
4. **Отношения: порядок и пустое состояние.** Сейчас порядок — как пришло из
   данных; нужен устойчивый (по имени либо по прогрессу) и внятная строка,
   когда никого ещё не встретил.

**Готово, когда:** ни одно объявленное поле не остаётся невидимым; каждая
секция имеет пустое состояние; `Minimal` по-прежнему даёт имя + ID и ничего
лишнего; переполнений на матрице устройств нет.

**Спросить у Ильи до начала:** показывать ли кошелёк в профиле, раз он есть в
шапке; откуда берутся аватары.

## 5. Разминка на первый день

Взять любую из этих — маленькие, независимые, дают почувствовать слой:

- Прогнать оба экрана на матрице устройств (iPhone SE3 / 15 / 16 Pro Max /
  1080×2340 / 20:9 / iPad 4:3) и завести задачи на переполнения. Систематически
  это никем не проверено.
- Найти в оболочке места, где цвет или отступ заданы числом мимо токенов, и
  свести к токенам. `grep -n "style.backgroundColor = new Color" unity/Packages/com.lvn.engine.shell/Runtime/*.cs`

## 6. Где спрашивать

Непонятно, куда класть код, — смотри `where-things-live.md`: там перечислены
все дома движка и оболочки с объяснением, зачем каждый заведён. Если работа не
ложится ни в один дом — это либо новый дом, либо она стоит не на своём этаже;
и то и другое стоит обсудить, а не решать молча.
