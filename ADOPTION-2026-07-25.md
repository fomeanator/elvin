#### U3 [HIGH] «В Unity — 2 минуты» пропускает именно тот шаг, на котором новичок видит пустой экран

README, 3 шага: добавить пакет → бросить `.lvns` в `Assets/` → повесить

Реально нужно ещё: создать **PanelSettings**, создать/назначить

#### U4 [HIGH] Unity-путь не получает валидации вообще

`LvnsImporter.cs` вызывает только `LvnsCompiler.Compile`. Валидатора в C# **не
существует**: `grep -rln "undefined label\|LvnValidat\|Validator"
unity/Packages/ --include=*.cs` → ноль файлов.

А `convert` без `validate` битые переходы пропускает:

```
$ lvnconv convert -i d.lvns -o d.lvn      # 'Hi.' + '- Go -> nowhere'
rc=0
$ lvnconv validate d.lvn
error: script[1] choice: jump to undefined label "nowhere"
FAIL: 1 error(s), 0 warning(s)
```

Следствие: автор, работающий так, как README рекламирует главным образом
(«Drop a `.lvns` file into `Assets/` — Unity compiles it on import»), **никогда
не видит валидатор**. Битый переход импортируется чисто, а в рантайме молча
завершает историю (в JS-плеере это даже закомментировано: «dangling jump ends
the story (validator catches it upstream)» — вот только upstream в Unity не
запускается). Обещание README «Dangling jumps, unknown ops, dead labels —
caught at build time, not in a player's hands» для этого пути **неверно**.

README продаёт лаконичный Elvin Script (`bg /content/bg/…`,

#### A3 [CRITICAL] Опечатка в имени op'а с позиционным аргументом молча превращается в реплику — гейт зелёный

Самая дорогая находка для ставки «ИИ пишет → компилятор ловит». Защита
(`looksLikeCommand`, `convert.go:1245`) требует, чтобы **все** слова после
первого были `key=value`. Ops с позиционными аргументами — то есть
`bg`, `show`, `hide`, `goto`, `audio`, `wait`, `label` — под неё не попадают.

Прогнал матрицу через CLI (идентично через wasm — playground, VS Code, IDE — и
через MCP `lvns_check`):

```
bbg /path/a.jpg      => OK: 2 command(s), 0 warning(s)     ← молча
shwo mara            => OK: 2 command(s), 0 warning(s)     ← молча
shwo mara at=left    => OK: 2 command(s), 0 warning(s)     ← молча
hidee mara           => OK: 2 command(s), 0 warning(s)     ← молча
jmp somewhere        => OK: 2 command(s), 0 warning(s)     ← молча
iff x > 1 -> y       => OK: 2 command(s), 0 warning(s)     ← молча
sett x = 1           => warning: … mistyped command "sett" … (it became dialogue text)
foobarop x=1         => ERROR: unknown command "foobarop"
chioce timeout=5     => ERROR: unknown command "chioce" — did you mean "choice"?
```

Контейнер для первого случая:

```json
{"op":"say","text":"bbg /content/bg/Autumn_street.jpg"}
{"op":"say","text":"shwo mara"}
```

Игрок буквально прочитает вслух `bbg /content/bg/Autumn_street.jpg`.

Три отдельные беды:
1. **Молчание.** Прямое противоречие принципу «Unknown is an error, never a
   silent skip», причём именно на самом частом классе ошибок LLM — промахе в
   имени op'а на один символ.
2. **Непоследовательность строгости.** Один и тот же класс опечатки даёт то
   hard error (`chioce`), то warning (`sett`), то тишину (`shwo`). Агент не
   может вывести правило.
3. **`iff x > 1 -> y` — худший случай:** вся ветка `-> y` проглатывается вместе
   со строкой, поэтому проверка висячих переходов её даже не видит. Скрипт с
   потерянной веткой проходит гейт «0 варнингов» на отлично.

Пока это так, «зелёный гейт» не является доказательством корректности, и главный
цикл ставки протекает.

#### A4 [MEDIUM] `llms.txt` не опубликован, а его ссылки не разрешаются вне репозитория

Конвенция llms.txt — файл по адресу `https://домен/llms.txt` с абсолютными
ссылками. Проверил живой сайт:

```
llms.txt              404
howto/AGENTS.md       404
howto/CHEATSHEET.md   404
docs/playground.md    404
docs/                 200
```

`pages.yml` кладёт в `_site` только playground в корень и `docs/` (HTML/CSS/JS +
плоский `content/`). Ни `llms.txt`, ни сырых markdown там нет. При этом сам
`llms.txt` состоит из относительных ссылок (`howto/AGENTS.md`,
`docs/playground.md`) — их не разрешить ни с сайта, ни с raw-URL. Работают они
только при просмотре репозитория на GitHub. То есть «Point your agent at
`llms.txt`» сегодня означает «дай агенту склонированный репозиторий».

#### A5 [MEDIUM] Ни один документ не даёт агенту (и человеку) запускаемую ссылку

12 жанровых руководств провожают читателя текстом и `.lvns`-файлом. Ни в одном
нет «▶ открыть в playground». Хотя, как показано выше, **все 12 играют** —
достаточно сгенерировать `#s=<base64>`.

#### X1 Контракт op'ов расходится по рантаймам — подтверждаю T2 независимо

## 4. Чего НЕ надо делать

- **Не добавлять op'ы.** 30 — это достоинство, а не недоделка. Каждый новый op
  умножается на ×4 реализации (X1) и на объём доков. `wardrobe_show` уже
  показал цену: добавлен в `KnownOps` и `grammar.json`, реализован в shell —
  и у потребителя публичного UPM-пакета он тихий no-op.
- **Не догонять Unity веб-плеером.** Не надо портировать частицы, кости, Spine,
  камеру в JS. Честное подмножество мини-плеера — это фича (все 12 жанров в нём
  играют!). Нужно **точно объявить** подмножество, а не расширять его.
- **Не трогать playground и HTML-экспорт как продукт.** Это измеренно лучшая
  часть: экспорт самодостаточен, играет с диска, сейвит. Единственная правка —
  дрейф сейва (W1). Любой редизайн тут — потеря.
- **Не писать больше прозы в доки.** В `howto/` уже 1705 строк, 66 markdown в
  сумме — это больше, чем новичок прочитает. Дефицит не в тексте, а в
  **запускаемых входах** (кнопка в playground, MenuItem, работающий `lvn_doc`).
  Написать ещё документ — самый соблазнительный рефлекс и он воронку ухудшит.
- **Не менять хранилище сервера ради адопшна.** Ноль баз данных и один бинарь —
  ровно то, из-за чего «любой поднимет за минуту» правда. (Потолок для живого
  биллинга — отдельный вопрос, к принятию не относится.)
- **Не идти в Unity Asset Store до №9 и №10.** Листинг без one-click-обвязки и
  без валидации в импортёре получит отзывы «пустой экран, ничего не работает», и
  этот первый залп отзывов уже не переписать.
- **Не локализовать доки.** Английский для этой аудитории верен. Единственный
  русский артефакт (герой-скриншот) надо сделать английским, а не наоборот.
- **Не строить GUI-визард онбординга в Studio.** Zero-install путь уже есть — это
  playground. Второй онбординг разделит внимание и удвоит поддержку.
- **Не «чинить» пункт 9 в `AGENTS.md` про missing art формулировкой.** Проблема
  X3 не в том, что доки недостаточно оправдывают чёрный экран, а в том, что
  чёрный экран не должен выглядеть как поломка. Это правка greybox'а, не текста.

## 6. Итог одной строкой

Продукт лучше, чем путь к нему, и разрыв сосредоточен в трёх местах, где
**документированный** первый шаг просто не работает: `-studio` на свежем клоне
(человек), `lvn_doc` при штатной установке MCP (агент) и молчаливое проглатывание
опечатки в имени op'а (оба). Playground с HTML-экспортом — готовая, проверенная,
лучшая в проекте воронка, которой не хватает только ссылок из доков, чтобы в неё
кто-то вошёл.
